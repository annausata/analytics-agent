# Course Analytics Agent

Streamlit-дашборд із вбудованим агентом, який відповідає на запитання про базу
даних онлайн-платформи курсів звичайною мовою: сам пише SQL, виконує його в
режимі «тільки читання», рахує статистику й пояснює результат українською.

```
питання → Gemini пише SQL → перевірка безпеки → PostgreSQL → статистика → пояснення
```

---

## Що робить агент

### 1. Відповідає на запитання про дані

Користувач пише запитання у чаті — наприклад «скільки записів на курси було у
січні 2022?». Агент виконує п'ять кроків:

| Крок | Що відбувається |
|---|---|
| 1. Схема | Зчитує структуру БД з `information_schema` (кешується) |
| 2. Генерація SQL | Gemini пише **один** read-only запит за схемою + доменними примітками |
| 3. Перевірка | `validate_sql()` відхиляє все, що не є читанням |
| 4. Виконання | Запит іде в транзакції `READ ONLY` з таймаутом 10 с |
| 5. Пояснення | Gemini перетворює таблицю + статистику на текст українською |

Якщо PostgreSQL повертає помилку, агент робить **одну спробу самовиправлення**:
показує моделі текст помилки й просить виправлений запит.

### 2. Відповідає на запитання про саму базу

Запитання на кшталт «які є таблиці і як вони пов'язані?» не має відповіді у
вигляді SQL. У такому разі модель повертає `CANNOT_ANSWER`, агент перехоплює це
як `CannotAnswerWithSQL` і відповідає **зі схеми**, без звернення до бази.

### 3. Показує дашборд

Ключові метрики, місячна динаміка (записи / сертифікація / дохід) і топ доменів.
Дашборд — це чистий SQL, він **не витрачає запитів до Gemini** і працює навіть
без API-ключа.

### Захист від небезпечного SQL

Два незалежні рівні:

1. **`validate_sql()`** — дозволені лише `SELECT` і `WITH`; одна команда
   (`;` всередині заборонено); блокування `INSERT/UPDATE/DELETE/DROP/ALTER/
   TRUNCATE/CREATE/GRANT/REVOKE/MERGE`, у тому числі у CTE на кшталт
   `WITH x AS (DELETE ... RETURNING *)`; коментарі вирізаються, щоб у них не
   можна було сховати заборонене слово; якщо `LIMIT` відсутній — додається
   `LIMIT 500`.
2. **З'єднання з БД** відкривається як `READ ONLY`, тому навіть пропущена
   команда не виконається.

## Які дані він використовує

PostgreSQL-база онлайн-платформи курсів (Coursera-подібна), 11 таблиць:

| Таблиця | Рядків | Про що |
|---|---:|---|
| `users` | 40 000 | Користувачі: дата реєстрації, країна, тариф, персона, пристрій |
| `enrollments` | 94 705 | Записи на курси: прогрес, етап воронки, сертифікація |
| `payments` | 87 924 | Платежі: сума, тариф, ознака повернення |
| `weekly_activity` | 84 618 | Потижнева активність: хвилини перегляду, тести |
| `reviews` | 158 467 | Відгуки та зіркові оцінки |
| `review_link` | 811 | Зв'язок відгуків із записами (покриває <1 % відгуків) |
| `dim_course` | 3 032 | Довідник курсів: домен, рівень, партнер, рейтинг |
| `courses_content` | 13 063 | Структура курсів за тижнями |
| `weeks_content` | 157 226 | Навчальні матеріали всередині тижнів |
| `specializations` | 728 | Спеціалізації |
| `specialization_content` | 3 042 | Курси у складі спеціалізацій |

**Зв'язки:** `enrollments` — центральна таблиця: `user_id → users`,
`course_id → dim_course`, `enrollment_id ← weekly_activity`.
`payments.user_id → users`. `reviews.course_url → dim_course`.

### Особливості даних, які враховує агент

Ці знання неможливо прочитати з `information_schema`, тому вони зашиті в
`agent.SCHEMA_NOTES` і додаються до промпту:

* **`enrolled_at` — це TEXT у ДВОХ форматах:** 90 919 рядків `YYYY-MM-DD` і
  3 786 рядків `DD.MM.YYYY`. Звичайний `::date` падає на ~4 % таблиці.
* **`review_date` — третій формат:** `'Feb 14, 2023'`.
* **Дані закінчуються 2023-02-26**, тому `CURRENT_DATE` дає порожній результат —
  для запитань «за останній місяць» треба спиратися на `max()` у самих даних.
* **Чистий дохід** рахується лише по `is_refunded = 0`.
* **Воронка:** `registered → viewed → explored → certified`.
* **Частки з малої вибірки** відсікаються (`HAVING count(*) >= 100`), а у
  відповіді поряд із відсотком завжди називається обсяг вибірки.

## Як запустити проєкт

### 1. Залежності

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
```

### 2. Налаштування

```bash
cp .env.example .env
```

Заповнити у `.env` два значення:

* `DATABASE_URL` — рядок підключення до PostgreSQL;
* `GEMINI_API_KEY` — ключ із [Google AI Studio](https://aistudio.google.com/apikey).

`.env` занесено в `.gitignore` — його не можна комітити.

### 3. Запуск

```bash
./.venv/bin/streamlit run app.py
```

Відкриється на `http://localhost:8501`.

### Запуск агента без інтерфейсу (для налагодження)

```bash
./.venv/bin/python agent.py "скільки всього сертифікатів видано?"
```

Виводить згенерований SQL, таблицю результату й відповідь — зручно, щоб
побачити, що саме написала модель.

## Обмеження безкоштовного тарифу Gemini

Безкоштовний тариф дає **20 запитів на добу на КОЖНУ модель окремо**, а одне
запитання коштує **2 запити** (SQL + пояснення). Тобто ≈ 10 запитань на добу.

Якщо з'явиться `429 RESOURCE_EXHAUSTED` — агент покаже зрозуміле повідомлення й
**не буде** марно повторювати спробу. Достатньо вказати іншу модель у `.env`
(у кожної власна квота) і перезапустити застосунок:

```bash
GEMINI_MODEL=gemini-3.7-flash
```

Перевірені моделі: `gemini-3-flash-preview`, `gemini-3.7-flash`,
`gemini-3.8-flash`, `gemini-3.5-flash`. Повний список доступних ключу:

```bash
./.venv/bin/python -c "import agent; [print(m.name) for m in agent._client().models.list()]"
```

> **Важливо:** значення з `.env` зчитуються **один раз при старті**. Після зміни
> файлу застосунок треба перезапустити.

Тимчасові помилки `503 UNAVAILABLE` («модель перевантажена») агент повторює
автоматично — 4 спроби з подвоєнням паузи.
